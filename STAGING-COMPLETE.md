## 🚀 Quick Start Guide

### 1. Create Staging Database
```bash
npx wrangler d1 create ludo-arena-staging-db --env staging
# Copy the database_id from output
```

### 2. Update wrangler.toml
Uncomment lines 71-74 and replace `YOUR_STAGING_DATABASE_ID` with the actual ID.

### 3. Configure Secrets
```bash
# On Linux/Mac
./scripts/setup-staging-secrets.sh

# On Windows
./scripts/setup-staging-secrets.ps1
```

### 4. Run Migrations
```bash
npm run db:migrate:staging
```

### 5. Deploy
```bash
npm run deploy:staging
```

### 6. Verify
```bash
# Check deployment
curl https://ludo-arena-multiplayer-staging.YOUR_SUBDOMAIN.workers.dev/api/health

# Stream logs
npx wrangler tail --env staging
```

## 🎯 Key Features of Staging Environment

- **Isolated Database**: Separate D1 database from production
- **Separate Secrets**: Own OAuth credentials and session secrets
- **Lower Voice Limits**: 2,000 minutes/month vs 8,000 in production
- **Safe Testing**: No impact on production users or data
- **Full Feature Parity**: Same features as production
- **Easy Deployment**: Single command deployment
- **Automatic Backups**: Built-in backup scripts

## 💡 Tips

- Use staging to test new features before production
- Run smoke tests after each deployment
- Keep staging secrets separate from production
- Clear staging database periodically for fresh testing
- Monitor logs during and after deployment
- Create backups before running migrations
